# FRP 访问控制与端口保留

## 访问模式

FRP 启用开关控制设备是否建立反向隧道；「公网直连」开关只控制分配给该设备的 SSH/Web 映射端口能否从非本机来源直接访问，不负责启停 FRP。

- 公网直连开启：宿主更新器在 IPv4 和 IPv6 防火墙中为设备的 SSH/Web TCP 端口写入精确 ACCEPT 规则。
- 公网直连关闭：对应端口写入精确 DROP 规则，但规则排除 loopback。
- 关闭公网直连不会关闭 FRP。`jetson_remote` 先 SSH 到 212，再经 212 的 `127.0.0.1:<映射端口>` 转发；这条管理路径继续可用。
- 开启公网直连前必须有新版本宿主更新器的有效心跳。关闭直连会先持久化关闭期望策略；若更新器暂不可用，界面明确显示未应用，不能把它当作已关闭。

## 端口分配

设备首次启用 FRP 时分配 SSH `N` 和 Web `N+1`。设备停用 FRP 仅关闭隧道并保留端口，不会释放或自动重排。重新启用同一设备会继续使用原端口对。只有设备确认隧道已断开后，管理员才能双击端口修改或使用「重置端口」分配其他空闲端口对。端口池调整不能自动迁移已保留端口；必须先逐台停用并明确重置。

## 宿主影响与边界

本功能由平台生成 `/run/platform-updates/frp-firewall-policy.json`，由宿主机 `device-platform-updater.service` 以 root 身份调用 `iptables` 和 `ip6tables` 对账。规则只匹配本平台标记、目标 TCP 端口和 INPUT 链；只删除内容完全匹配的 `dmp-frp-*` 规则，不清空防火墙、不改 SSH 服务、不改默认策略、不重启主机。规则跨地址族应用失败时，更新器会回滚本轮改动；回滚失败会在共享状态明确报错。

首次升级后的已有设备默认关闭公网直连。宿主控制器确认可用后，平台开始对其已保留端口应用私有访问规则。此处会修改主机防火墙，部署前应确认 `jetson_remote` 的回环转发可用，并避免用直接公网端口验证管理通道。

## API

- `GET /api/frp/`：返回设备映射、直连设置和宿主策略状态。
- `PATCH /api/frp/<device_id>/public-access/`，管理员：`{"enabled": true|false}`。
- `PATCH /api/frp/<device_id>/ports/`，管理员：仅传 `ssh_port` 或 `web_port` 之一。
- `POST /api/frp/<device_id>/ports/reset/`，管理员：重置为其他空闲相邻端口对。

变更先写入数据库和原子策略快照，宿主守护进程随后应用。`pending`、`unavailable` 或 `error` 均表示尚不能确认规则已生效。恢复时通过 FRP 管理页切回原访问模式；若需要清理宿主规则，只清理由本更新器标记的精确规则，不执行全局防火墙清空操作。
