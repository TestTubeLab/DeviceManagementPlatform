# 使用手册

## 一、设备管理

### 1.1 查看设备列表

访问 `http://your-cloud.com/admin/management/device/`

**设备状态说明**：
- 🟡 **等待部署**: 设备已注册，等待部署主应用
- 🔵 **部署中**: 正在下载镜像和配置
- 🟢 **在线**: 设备正常运行，定时心跳
- 🔴 **离线**: 5分钟内无心跳（可能断电/断网）
- 🟠 **更新中**: 正在执行OTA更新
- ⚠️ **异常**: 部署失败或运行错误

### 1.2 添加新设备

**方法1：设备自动注册（推荐）**

在新设备上运行安装脚本，设备会自动注册：
```bash
curl -fsSL http://your-cloud.com/install.sh | bash
```

**方法2：手动添加**

在管理后台点击 **添加设备**，填写：
- 设备ID: `dev_xxx`（必填）
- 名称: 如 "生产线A - 1号设备"
- 位置: 如 "北京工厂 - 2车间"

### 1.3 部署项目到设备

1. 进入设备详情页
2. 点击 **部署** 按钮
3. 填写部署配置：

   | 配置项 | 说明 | 示例 |
   |-------|------|------|
   | 目标版本 | 要部署的版本号 | `v1.0.3` |
   | 反向Socket主机 | 上位机IP地址 | `192.168.31.29` |
   | 反向Socket端口 | 通信端口 | `9088` |

4. 点击 **确认部署**
5. 查看部署进度（自动刷新）

**部署时间**：约3-5分钟（取决于网速）

### 1.4 查看设备详情

点击设备进入详情页，可查看：

- **基本信息**: ID、名称、位置、MAC地址、IP地址
- **运行状态**: 当前版本、在线状态、最后心跳时间
- **性能指标**: CPU/内存/磁盘使用率（实时更新）
- **配置信息**: JSON格式的设备配置
- **操作日志**: 最近50条日志

## 二、OTA远程更新

### 2.1 批量更新设备

1. 进入 **更新管理** 页面
2. 点击 **批量更新** 按钮
3. 选择要更新的设备（可多选）
4. 输入目标版本号（如 `v1.0.4`）
5. 点击 **开始更新**

系统会为每台设备创建更新任务，设备在下次心跳时自动执行。

### 2.2 查看更新进度

在 **更新任务** 列表中查看：

| 状态 | 说明 |
|-----|------|
| ⏳ 等待中 | 任务已创建，等待设备心跳 |
| ⬇️ 下载中 | 正在拉取新镜像 |
| 📦 安装中 | 正在替换容器 |
| ✅ 成功 | 更新完成 |
| ❌ 失败 | 更新失败，查看错误信息 |

### 2.3 更新失败处理

如果更新失败：

1. 查看错误信息（点击任务查看详情）
2. 常见错误：
   - **镜像拉取失败**: 检查Registry地址和网络
   - **容器启动失败**: 检查配置文件
   - **健康检查超时**: 新版本可能有问题，建议回滚

3. 重试更新：
   - 删除失败的任务
   - 重新创建更新任务

### 2.4 回滚版本

目前暂不支持自动回滚，如需回滚：

1. 创建新的更新任务，指定旧版本号
2. 或者SSH到设备手动操作：
   ```bash
   docker pull registry:5000/middleware:v1.0.2
   docker stop middleware && docker rm middleware
   # 重新启动旧版本容器
   ```

## 三、配置管理

### 3.1 修改设备配置

1. 进入设备详情页
2. 点击 **编辑配置** 按钮
3. 修改JSON配置（如修改相机IP）：
   ```json
   {
     "reverse_socket_host": "192.168.31.29",
     "reverse_socket_port": 9088,
     "camera_ip": "192.168.1.100"
   }
   ```
4. 点击 **保存并同步**

配置会在下次心跳时自动同步到设备，并触发容器重启。

### 3.2 批量修改配置

适用于多台设备修改相同配置项：

1. 进入 **批量配置** 页面
2. 选择设备（可多选）
3. 选择配置项（如 `reverse_socket_host`）
4. 输入新值
5. 点击 **批量应用**

## 四、日志管理

### 4.1 实时查看日志

在设备详情页点击 **实时日志**，查看最新100条日志（自动刷新）。

**日志级别过滤**：
- ⚪ DEBUG: 调试信息
- 🔵 INFO: 一般信息
- 🟡 WARNING: 警告信息
- 🔴 ERROR: 错误信息
- 🚨 CRITICAL: 严重错误

### 4.2 下载日志

点击 **下载日志** 按钮，选择日期范围，下载CSV格式日志文件。

### 4.3 日志告警

在 **告警规则** 中配置：

- **ERROR级别**: 出现即推送通知
- **CRITICAL级别**: 立即电话告警

通知方式：邮件、微信、钉钉

## 五、监控告警

### 5.1 设备监控大屏

访问 `http://your-cloud.com/dashboard/`

**实时显示**：
- 设备总数 / 在线数 / 离线数
- CPU/内存/磁盘使用率（柱状图）
- 最近部署任务
- 最近更新任务
- 异常告警

### 5.2 配置告警规则

在 **告警规则** 页面：

1. 点击 **新建规则**
2. 选择告警类型：
   - 设备离线（超过X分钟）
   - CPU使用率超过X%
   - 内存使用率超过X%
   - 磁盘使用率超过X%
   - 部署失败
   - 更新失败

3. 设置阈值和通知方式
4. 保存规则

**示例规则**：
```
设备离线 > 10分钟 → 发送邮件通知
CPU使用率 > 90% → 发送钉钉通知
磁盘使用率 > 85% → 发送微信通知
```

## 六、镜像管理

### 6.1 构建新镜像

在本地（开发机）构建并推送：

```bash
# 进入主项目目录
cd /path/to/MiddlewareServer

# 构建镜像
docker build -t middleware:v1.0.4 .

# 打标签
docker tag middleware:v1.0.4 your-cloud.com:5000/middleware:v1.0.4

# 推送到私有Registry
docker push your-cloud.com:5000/middleware:v1.0.4
```

### 6.2 查看镜像列表

访问私有Registry API：

```bash
# 查看所有镜像
curl http://your-cloud.com:5000/v2/_catalog

# 查看某镜像的所有版本
curl http://your-cloud.com:5000/v2/middleware/tags/list
```

### 6.3 清理旧镜像

定期清理Registry中的旧版本：

```bash
# 登录服务器
ssh root@your-cloud.com

# 清理未使用的镜像
docker exec device-mgmt-registry registry garbage-collect /etc/docker/registry/config.yml
```

## 七、API使用

### 7.1 认证

使用Token认证：

```bash
# 获取Token
curl -X POST http://your-cloud.com/api/auth/token/ \
  -H "Content-Type: application/json" \
  -d '{"username": "admin", "password": "your_password"}'

# 响应
{
  "token": "abc123def456..."
}
```

在后续请求中携带Token：

```bash
curl -H "Authorization: Token abc123def456..." \
  http://your-cloud.com/api/devices/
```

### 7.2 常用API

**获取设备列表**：
```bash
GET /api/devices/
```

**获取设备详情**：
```bash
GET /api/devices/{device_id}/
```

**创建部署任务**：
```bash
POST /api/deployments/
{
  "device": 1,
  "target_version": "v1.0.3",
  "config": {
    "reverse_socket_host": "192.168.31.29"
  }
}
```

**批量更新**：
```bash
POST /api/devices/batch_update/
{
  "device_ids": ["dev_001", "dev_002"],
  "version": "v1.0.4"
}
```

完整API文档：[API.md](API.md)

## 八、常见问题

### Q1: 设备长时间停留在"部署中"状态

**原因**：
- 网络不稳定，镜像下载慢
- Registry无法访问
- 设备存储空间不足

**解决**：
1. 检查设备日志：`journalctl -u bootstrap-agent -f`
2. 检查网络连通性：`ping your-cloud.com`
3. 检查磁盘空间：`df -h`

### Q2: 设备显示离线但实际在运行

**原因**：心跳上报失败

**解决**：
1. 检查设备端agent是否运行：`ps aux | grep device-agent`
2. 检查网络连接
3. 手动触发心跳测试

### Q3: 更新后服务无法启动

**原因**：新版本配置不兼容

**解决**：
1. 查看容器日志：`docker logs middleware`
2. 回滚到旧版本
3. 修复配置后重新更新

### Q4: 无法访问管理后台

**原因**：Nginx或Django容器异常

**解决**：
```bash
docker ps  # 检查容器状态
docker logs device-mgmt-nginx
docker logs device-mgmt-web
```

## 九、最佳实践

### 9.1 版本管理

- 使用语义化版本号：`v主版本.次版本.修订号`
- 每次发布前在测试环境验证
- 保留至少3个历史版本的镜像

### 9.2 配置管理

- 敏感信息（密码）使用环境变量
- 设备特定配置存储在数据库
- 定期备份配置

### 9.3 监控告警

- 设置合理的告警阈值
- 避免告警疲劳（频繁误报）
- 定期检查设备列表，清理废弃设备

### 9.4 日志管理

- 定期下载重要日志到本地
- 服务器端日志保留30天
- 设备端日志保留7天
