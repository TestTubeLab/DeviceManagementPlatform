| P2 | 日志批量串行执行长时间阻塞心跳 | 新 Agent 每次领取 1 个任务，旧客户端仍默认 5；未领取任务保留 pending |
| P2 | 新路径/字符串方法不兼容较早设备 Python | 使用 Python 3.8 兼容写法并做语法与功能回归验证 |

## 验证结果

- 本地及发布候选 Linux 镜像中，后台完整测试 **82/82 通过**。
- Agent 测试本地 **48 通过、1 跳过**（Windows 创建符号链接权限限制）；Linux 候选镜像中 **49/49 通过**。
- 前端定向交互回归 **14/14 通过**，TypeScript 与生产构建通过；保留既有大分块提示。
- Linux 真实子进程管道、有界截断和只读 systemd journal 查询通过。
- 数据库副本及正式迁移通过；迁移前后既有业务表内容指纹一致，历史日志任务完成独立转存。完成的过期日志任务后续按既定 7 天策略清理。
- 公网验证仪表盘、设备、项目、任务、FRP 和系统日志页面正常，未捕获页面异常或 API 500；390px 页面无横向溢出。
- 新容器健康，数据库完整性正常；FRP 和 Registry 未重启，既有在线设备继续心跳。

## 发布与恢复资料

- 镜像版本：`device-platform:1.7.3-20261118`，现有 Compose 应用标签同步为 `deploy-simple-app`。
- Agent 发布版本：`1.7.3`，现有自动更新机制继续使用；本次未强制所有现场设备升级或重新部署业务项目。
- 发布暂存目录：`/root/deploy_uploads/device-platform-1.7.3-20261118`。
- 备份目录：`/root/deploy_backups/device-platform-1.7.3-20261118-104153`。
- 备份包含切换前数据库 `db-cutover.sqlite3`、约 3.18 GB 的 `media-before.tar`、原宿主机源码、原容器配置和上传文件清单。原镜像保留为 `device-platform:rollback-1.7.3-20261118`。
- 正式切换前后 10 个上传文件的大小和 SHA-256 均一致。设备、项目、代码包、部署记录和用户内容指纹在迁移阶段保持一致。
- 暂存目录的 `rollout.py` 含本次自动失败恢复逻辑，`release-result.json` 记录在备份目录。不要再次执行已成功完成的发布脚本。

正常运行一段时间后的回滚应先暂停平台写入，参考 [SYSTEM_LOGS.md](SYSTEM_LOGS.md) 将日志任务反迁移至兼容结构，再恢复旧镜像。不能直接用切换前数据库覆盖正在运行的数据库，否则会丢弃发布后数据。

## 保留的边界

- 旧 Agent 的公开通信接口继续兼容。若需要逐设备认证，应另行制定凭据分发与迁移方案，不能直接封闭现有接口。
- 旧设备、项目、任务等列表超过默认前 100 条时，部分页面仍缺少完整分页；当前现网数量未触及该边界。新系统日志页面已分页。
- 真实 Jetson 相机、业务容器更新和外部镜像仓库拉取未作为本次线上验证的变更操作；没有为测试而替现场设备下发业务部署。
- Python 3.8 做了语法兼容检查，实际 Linux 发布运行于 Python 3.10；这不替代旧设备真实解释器验证。
