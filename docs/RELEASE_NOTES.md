# 发布记录

## 1.7.3 — 系统日志与发布前审查修复

- 在 FRP 管理下方增加系统日志，包含平台操作/异常与设备日志；后台和 Agent 版本同步为 1.7.3。
- 管理端项目、代码包、镜像和任务写操作校验登录。保留现有 Agent 的轮询、进度回传与代码包下载接口，避免已部署设备中断升级。
- 镜像接口兼容 JSON 与 multipart，补齐镜像部署任务提供给 Agent 的信息。上传代码包使用独立 UUID 存储名称，防止名称包含路径或同秒上传覆盖旧包。
- 配置历史以纯文本展示；设备编辑草稿不再被后台刷新覆盖，任务详情随列表刷新同步状态。
- 新旧日志窗口统一行数上限、超时与取消行为；Agent 保留 Python 3.8 可用的路径校验，按单任务领取日志以减少主循环长时间阻塞。
- 代码包先完整验证、暂存解压后再替换，替换失败恢复旧代码，并保留已存在的运行数据。
- 容器启动时数据库迁移失败即停止，不再用手工补表掩盖部分迁移失败。

系统日志接口、保留策略和迁移回滚步骤见 [SYSTEM_LOGS.md](SYSTEM_LOGS.md)。

### 发布与数据保护

本版本复用当前生产 Docker 镜像的 Python 和系统依赖。仅更新应用代码、Agent 下载脚本和前端产物；不更新 FRP、Registry，不删除或替换业务数据卷。

上线前保留原镜像、运行文件与数据库快照，在数据库副本上先验证迁移。正式迁移时暂停平台应用写入，核对设备、项目、代码包、任务与用户记录，并确认上传文件清单与校验和一致后恢复服务。

Agent 沿用现有自动更新机制。发布新的 Agent 下载脚本不直接下发项目部署任务，不重启设备业务容器。实际 Jetson 硬件和现场相机验证仍独立于平台发布验证。

### 已知边界

- 旧 Agent 通信沿用现有兼容协议，本次不进行全设备认证协议迁移。
- 旧设备、项目和任务页面仍消费后端默认的前 100 条记录；超过该数量时需要后续增加完整分页或远程搜索。新系统日志页面已有分页，其设备选择器会遍历分页加载。
