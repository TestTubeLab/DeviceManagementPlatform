## 平台简介

### 平台解决什么问题？

当你有多台边缘设备（开发板）需要部署相同的业务代码时，传统方式需要：
- 逐台 SSH 登录
- 手动上传代码
- 手动启动容器
- 无法统一监控状态

**本平台提供**:
- ✅ 一键部署代码到多台设备
- ✅ 实时监控设备在线状态
- ✅ 统一管理部署任务
- ✅ 支持代码热更新（无需重建镜像）

### 核心概念

| 概念 | 说明 |
|------|------|
| **项目** | 你的业务应用（包含代码包 + 运行配置） |
| **设备** | 安装了 Agent 的边缘开发板 |
| **本地镜像** | 设备上预装的 Docker 镜像（包含环境依赖） |
| **代码包** | 你的业务代码 ZIP 压缩包 |
| **部署任务** | 平台下发到设备的部署指令 |

### 工作原理

```
你的操作                    平台                        设备
   │                         │                          │
   │  1. 上传代码包          │                          │
   │ ───────────────────────>│                          │
   │                         │                          │
   │  2. 选择设备，点击部署   │                          │
   │ ───────────────────────>│  3. 创建部署任务          │
   │                         │ ────────────────────────>│
   │                         │                          │
   │                         │  4. Agent 轮询到任务      │
   │                         │<────────────────────────│
   │                         │                          │
   │                         │  5. 下载代码，启动容器    │
   │                         │ ────────────────────────>│
   │                         │                          │
   │  6. 查看部署结果         │  7. 上报完成状态          │
   │<───────────────────────│<────────────────────────│
```

## 快速开始

### 第一步：访问平台

打开浏览器访问：`http://你的服务器IP:8081`

使用默认账号登录：
- 用户名：`admin`
- 密码：`admin123`

> ⚠️ 首次登录后请修改密码

### 第二步：设备安装 Agent

在每台需要管理的设备上执行：

```bash
curl -fsSL http://你的服务器IP:8081/api/install.sh | sudo bash
```

安装成功后，设备会自动出现在平台的"设备管理"列表中。

### 第三步：创建项目并部署

1. 进入"项目管理"
2. 点击"创建项目"
3. 填写配置（详见下文）
4. 点击项目的"部署"按钮
5. 选择目标设备
6. 点击"开始部署"

**功能**:

### 💻 设备管理

**路径**: 侧边栏 → 设备管理

**功能**:
- 查看所有已注册设备
- 查看设备在线状态
- 查看设备 IP、最后心跳时间
- 查看设备资源使用率 (CPU/内存/磁盘)

**设备状态说明**:

| 状态 | 含义 |
|------|------|
| 🟢 在线 | Agent 正常运行，5分钟内有心跳 |
| 🔴 离线 | 超过5分钟没有心跳 |
| 🟡 部署中 | 正在执行部署任务 |
| 🔴 异常 | 部署失败或其他错误 |

**设备详情页**:
- 点击设备 ID 进入详情
- 可编辑设备名称、位置
- 可设置"自动部署项目"（设备上线后自动部署）

---

### 📁 项目管理 ⭐ (核心功能)

**路径**: 侧边栏 → 项目管理

这是平台的**核心功能入口**，在这里：
- 创建/编辑项目
- 上传代码包
- 部署项目到设备

#### 创建项目

点击"创建项目"，填写以下信息：

| 字段 | 必填 | 说明 | 示例 |
|------|------|------|------|
| 项目名称 | ✅ | 项目的名称 | `MiddlewareServer` |
| 版本 | ✅ | 当前版本号 | `v1.0.0` |
| 描述 | | 项目描述 | `中间件服务` |
| **本地镜像名称** | ✅ | 设备上预装的 Docker 镜像 | `newserver:latest` |
| 代码包 | | 上传 ZIP 压缩的业务代码 | `code.zip` |
| 代码挂载路径 | | 代码在宿主机的存放位置 | `/opt/project-code` |
| 容器内工作目录 | | 代码在容器内的挂载位置 | `/work` |
| 启动命令 | ✅ | 容器启动后执行的命令 | `/start.sh` |
| 容器名称 | | Docker 容器名 | `middleware` |

#### 容器配置

| 选项 | 说明 |
|------|------|
| 启用 NVIDIA Runtime | 需要 GPU 时勾选，等同于 `--runtime nvidia` |
| 网络模式: host | 使用宿主机网络，等同于 `--network host` |
| 特权模式 | 访问硬件设备时勾选，等同于 `--privileged` |

#### 上传代码包

1. 在项目表单中，点击"代码包"旁的"上传"按钮
2. 选择 ZIP 压缩文件（包含你的业务代码）
3. 等待上传完成

> 💡 代码包建议控制在 100MB 以内，大文件传输较慢

#### 部署项目到设备

1. 在项目列表中，点击项目的"部署"按钮
2. 在弹出的对话框中：
   - 确认项目信息（镜像、代码包、启动命令）
   - 选择要部署的设备（可多选）
3. 点击"开始部署"
4. 前往"任务管理"查看部署进度

---

### 📋 任务管理

**路径**: 侧边栏 → 任务管理

**功能**:
- 查看所有部署任务
- 查看任务状态和进度
- 查看错误信息

**任务状态说明**:

| 状态 | 进度 | 含义 |
|------|------|------|
| 等待中 | 0% | 任务已创建，等待 Agent 获取 |
| 拉取代码 | 20-40% | 正在下载代码包 |
| 配置中 | 50% | 正在解压代码 |
| 启动中 | 70% | 正在启动 Docker 容器 |
| 完成 | 100% | 部署成功 ✅ |
| 失败 | - | 部署失败 ❌ (查看错误信息) |

## 完整操作流程

### 场景：首次部署新设备

#### 前提条件

- [ ] 云服务器已部署平台
- [ ] 边缘设备已安装 Docker
- [ ] 边缘设备已加载业务镜像 (`docker load -i newserver.tar`)
- [ ] 边缘设备可访问云服务器 (网络互通)

#### 步骤 1: 在设备上安装 Agent

```bash
# SSH 登录到设备
ssh user@设备IP

# 安装 Agent（一条命令）
curl -fsSL http://云服务器IP:8081/api/install.sh | sudo bash
```

预期输出：
```
✓ 下载Agent脚本成功
✓ 创建服务配置成功
✓ 启动服务成功
✓ 服务状态正常
========================================
Agent安装完成！
设备ID: DEV-xxxxxx
========================================
```

#### 步骤 2: 确认设备上线

1. 登录平台 Web 界面
2. 进入"设备管理"
3. 确认新设备显示为"在线"状态

> 如果设备不在线，检查 Agent 状态：`sudo systemctl status device-agent`

#### 步骤 3: 创建项目

1. 进入"项目管理"
2. 点击"创建项目"
3. 填写项目信息：

```
项目名称: MiddlewareServer
版本: v1.0.0
本地镜像名称: newserver:latest
代码挂载路径: /opt/project-code
容器内工作目录: /work
启动命令: /start.sh
容器名称: middleware

容器配置:
  ☑ 启用 NVIDIA Runtime
  ☑ 网络模式: host
  ☑ 特权模式
```

4. 上传代码包（ZIP 文件）
5. 点击"保存"

#### 步骤 4: 部署到设备

1. 在项目列表中找到刚创建的项目
2. 点击"部署"按钮
3. 选择目标设备
4. 点击"开始部署"

#### 步骤 5: 查看部署结果

1. 进入"任务管理"
2. 找到对应的部署任务
3. 等待状态变为"完成"

#### 步骤 6: 验证部署

SSH 到设备，检查容器运行状态：

```bash
# 查看容器
docker ps

# 预期输出
CONTAINER ID   IMAGE              COMMAND      STATUS        NAMES
abc123...      newserver:latest   "/start.sh"  Up 5 minutes  middleware

# 查看容器日志
docker logs middleware
```

### 场景：代码更新

当你修改了业务代码，需要更新到设备：

1. 将新代码打包成 ZIP
2. 进入"项目管理"
3. 编辑项目，上传新的代码包
4. 修改版本号（如 v1.0.0 → v1.0.1）
5. 点击"保存"
6. 点击"部署"，选择需要更新的设备
7. 开始部署

Agent 会自动：
- 停止旧容器
- 下载新代码
- 解压到指定目录
- 启动新容器

---

### 场景：批量部署多台设备

1. 确保所有设备已安装 Agent 并在线
2. 进入"项目管理"
3. 点击项目的"部署"按钮
4. 按住 Ctrl 多选设备（或全选）
5. 点击"开始部署"

平台会为每台设备创建独立的部署任务，可在"任务管理"中跟踪每台设备的进度。

## 常见问题解答

### Q1: 设备安装 Agent 后没有上线？

**排查步骤**:

```bash
# 1. 检查 Agent 服务状态
sudo systemctl status device-agent

# 2. 查看 Agent 日志
sudo journalctl -u device-agent -f

# 3. 常见错误
# - "获取设备信息失败: 401" → 服务器需要重新构建
# - "Connection refused" → 检查服务器 IP 和端口是否正确
# - "Connection timeout" → 检查网络是否互通
```

**解决方案**:
```bash
# 重新安装 Agent
curl -fsSL http://服务器IP:8081/api/install.sh | sudo bash
```

### Q2: 部署失败，提示"本地镜像不存在"？

**原因**: 设备上没有加载项目配置的 Docker 镜像

**解决**:
```bash
# 在设备上加载镜像
docker load -i 你的镜像.tar

# 确认镜像存在
docker images | grep 镜像名

# 确保项目配置的镜像名与实际一致
```

### Q3: 部署任务一直卡在"等待中"？

**原因**: Agent 没有轮询到任务

**排查**:
```bash
# 在设备上检查 Agent 日志
sudo journalctl -u device-agent -f

# 正常应该看到:
# "发现待执行的项目部署: #xxx"
# "开始执行项目部署..."
```

**可能原因**:
1. Agent 离线 → 重启 Agent: `sudo systemctl restart device-agent`
2. Agent 报 401 错误 → 服务器权限配置问题，需要重新构建
3. 设备 ID 不匹配 → 确认任务的目标设备与 Agent 设备 ID 一致

### Q4: 代码包上传失败？

**可能原因**:
1. 文件过大，超时 → 平台支持最大 5GB，但建议 100MB 以内
2. 网络不稳定 → 检查网络连接

**建议**:
- 代码包只包含业务代码，不要包含依赖库
- 大文件考虑使用其他方式传输（如 scp）

### Q5: 容器启动后立即退出？

**排查**:
```bash
# 在设备上查看容器日志
docker logs middleware

# 查看容器状态
docker ps -a | grep middleware
```

**常见原因**:
1. 启动命令错误 → 检查项目配置的"启动命令"
2. 代码有 bug → 检查日志中的错误信息
3. 依赖缺失 → 确保镜像包含所有依赖

### Q6: 如何查看设备上的部署结果？

```bash
# SSH 到设备

# 查看运行中的容器
docker ps

# 查看容器日志
docker logs -f 容器名

# 进入容器排查
docker exec -it 容器名 /bin/bash

# 查看代码目录
ls -la /opt/project-code/
```

### Q7: 如何停止/重启设备上的容器？

目前需要 SSH 到设备手动操作：

```bash
# 停止容器
docker stop middleware

# 重启容器
docker restart middleware

# 删除容器（下次部署会重新创建）
docker rm -f middleware
```

> 后续版本会支持从平台远程控制

### Q8: 平台如何更新？

```bash
# SSH 到云服务器
cd /root/DeviceManagementPlatform

# 拉取最新代码
git pull

# 重新构建
cd deployment/deploy-simple
docker-compose up -d --build
```
